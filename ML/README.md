# 사출성형 불량 예측 모델 (CN7 / RG3)

## 한눈에 보기

- **목표**: 사출성형 공정 센서값으로 불량품을 미리 예측
- **결과**: CN7은 어느 정도 예측 신호를 찾았지만 정확도는 제한적이고, RG3는 사실상 예측이 안 됨
- **원인 (두 가지가 겹쳐 있음)**
  1. CN7·RG3 공통: 불량 사례 자체가 너무 적음(CN7 17건, RG3 25건) — 배울 수 있는 사례가 적어 어떤 알고리즘을 쓰든 지표가 낮고 불안정함
  2. RG3만 추가로: 지금 갖고 있는 센서값과 불량 여부 사이에 통계적 연관성이 거의 없음(아래 "데이터셋의 한계" 참고) — 데이터를 더 모아도 지금 센서 항목만으로는 해결이 안 됨
- **결론**: 알고리즘을 더 정교하게 바꾼다고 해결되는 문제가 아니라, 데이터 자체의 한계에 부딪힌 상태

## 용어 설명 (비전공자용)

| 용어 | 뜻 |
|---|---|
| 단일 분리(train/test split) | 데이터를 한 번만 "학습용/평가용"으로 나눠서 점수를 재는 방법. 불량 사례가 적을 때는 어느 몇 건이 평가용에 들어가느냐에 따라 점수가 크게 흔들림 |
| 5-fold 교차검증(cross-validation) | 데이터를 5조각으로 나눠 4조각으로 학습·1조각으로 평가하는 것을 5번 반복(매번 평가 조각을 바꿔가며)해서 평균 낸 것. 모든 데이터가 최소 한 번은 평가에 쓰여서 점수가 훨씬 안정적임. 이 문서의 모든 수치는 이 방식으로 얻은 평균값 |
| SVM | 양품과 불량을 가장 잘 갈라놓는 경계선을 찾는 모델 |
| RandomForest | "온도가 얼마 이상이고 압력이 얼마 이하면 불량" 같은 규칙 나무를 여러 개 만들어 다수결로 판단하는 모델 |
| GaussianNB | 각 공정변수가 양품/불량일 때 주로 어떤 값 범위에 있는지 통계로 계산해 확률로 판단하는 모델. 셋 중 가장 단순함 |
| pseudo-labeling(의사라벨) | 라벨(양품/불량 정답)이 없는 데이터에 모델이 예측한 값을 임시 정답처럼 붙여서 학습에 같이 쓰는 방법 |
| precision(정밀도) | "불량"이라고 예측한 것 중 실제로 불량인 비율. 낮으면 가짜 경보(오탐)가 많다는 뜻 |
| recall(재현율) | 실제 불량 중 모델이 잡아낸 비율. 낮으면 불량을 많이 놓친다는 뜻 |
| f1 | precision과 recall을 같이 보는 점수. 둘 중 하나만 잘해서는 높게 안 나옴 |
| roc_auc | 모델이 양품과 불량을 구분하는 능력 자체를 보는 점수. **0.5 = 동전 던지기(구분 능력 없음), 1.0 = 완벽히 구분.** 1에 가까울수록 좋고, 0.5 근처면 그 모델은 사실상 아무것도 학습하지 못한 것 |

## 데이터셋의 한계

**1) 표본이 너무 적음 (CN7·RG3 공통)**

라벨(양품/불량 정답)이 붙은 데이터 자체가 CN7 1,211건 중 17건, RG3 1,182건 중 25건뿐이다. 어떤 모델이든 불량 사례 십여 건만 보고 "불량의 패턴"을 안정적으로 배우기는 어렵다. 실제로 평가 방법을 "단일 분리"에서 "5-fold 교차검증"으로만 바꿔도 CN7 RandomForest의 F1이 0(전부 양품으로만 예측)에서 0.34로 크게 달라졌다 — 즉 지금 나오는 낮은 점수 중 상당 부분은 알고리즘의 한계가 아니라 표본 수의 한계다.

**2) RG3는 센서값 자체가 불량과 관련이 없음 (RG3만의 문제)**

CN7은 그래도 신호가 있다 — 예를 들어 `Max_Injection_Speed`(최대 사출속도)는 불량 그룹에서 평균이 뚜렷하게 높게 나타나고, 이 변수와 불량 여부의 상관계수는 최대 0.33까지 나온다. 반면 **RG3는 24개 센서 컬럼 전체를 통틀어 불량 여부와의 상관계수가 최대 0.065**(사실상 무상관)였고, SVM/RandomForest/GaussianNB **어느 모델도 ROC-AUC가 0.41~0.53**(동전 던지기 수준)을 벗어나지 못했다. 표본을 늘리거나 모델을 바꿔봐도(CN7과 합쳐서 학습, 판정 임계값 재조정 등 — 아래 "시도한 것들" 표 참고) 개선되지 않았다.

즉 **CN7은 "사례가 적어서 정확도가 낮은" 상황**이고, **RG3는 "사례도 적고, 지금 측정 중인 센서 항목 자체에 불량을 구분할 정보가 없는" 상황**이다. RG3를 개선하려면 지금과 다른 센서/변수를 추가로 측정하거나, 훨씬 더 많은 불량 사례를 확보해야 한다 — 이 리포지토리의 코드·모델을 손보는 것으로는 해결되지 않는다.

## 시도한 것들

이 불균형 문제를 풀기 위해 실제로 시도하고, 효과를 검증하고, 채택/폐기한 과정이다.

| # | 시도 | 결과 | 채택 여부 |
|---|---|---|---|
| 1 | 가이드북 원본 방식 (SVM/RF/GaussianNB + 단일 train/test 분리 + pseudo-labeling) | 단일 분리라 테스트셋에 불량이 3~5건뿐 → recall이 분리 방법에 따라 0.0~1.0으로 요동 | 평가 방식 자체를 교체 |
| 2 | 복원추출 오버샘플링으로 불량 표본을 900건 이상까지 증폭 | 소수의 원본 표본(17~25건)을 그대로 반복 복제하다 보니 모델이 노이즈를 암기 → RG3 ROC-AUC가 무작위(0.5)보다 낮은 0.39까지 하락 | 폐기 |
| 3 | `class_weight='balanced'` / `'balanced_subsample'`로 대체 | 데이터를 늘리지 않고 손실 함수 쪽에서 불균형을 보정 → 더 안정적 | 채택 |
| 4 | pseudo-labeling을 예측 클래스별로 나눠서 선택 (가이드북 원본은 확신도 상위를 클래스 구분 없이 통째로 선택 → 양품 쪽으로만 쏠려 결국 "전부 양품" 예측으로 수렴하는 문제가 있었음) | 쏠림 문제는 해결했지만, 그래도 라벨 수가 너무 적어 가짜 라벨의 노이즈가 이득보다 큼 → 순수 지도학습보다 낮은 성능 | 기본값 OFF, 옵션으로 유지 (`--pseudo-label`) |
| 5 | GridSearchCV로 RandomForest 하이퍼파라미터 탐색 | CN7 기준 F1 0.39 → 0.41(교차검증) | 채택 (`n_estimators=300, max_depth=12`) |
| 6 | 평가 방식을 단일 분리 → 5-fold 층화 교차검증으로 전환 | 불량 표본 전체가 최소 한 번씩 평가에 사용되어 결과가 안정됨 | 채택 |
| 7 | CN7+RG3 데이터 통합 학습 (서로 부족한 표본을 보완할 수 있을지 확인) | RG3는 여전히 개선 없음(AUC 0.47), CN7은 오히려 하락(F1 0.337→0.286) | 폐기 |
| 8 | 판정 임계값(threshold)을 0.5 대신 교차검증으로 재탐색 | 표본이 적어 탐색 자체가 노이즈에 맞춰짐 → F1 0.36→0.26으로 하락 | 폐기 |
| 9 | RG3 성능 저하 원인 진단 (상관계수, 여러 모델의 ROC-AUC 비교) | 24개 센서 피처와 PassOrFail 라벨의 최대 상관계수 0.065, 모든 모델 ROC-AUC 0.41~0.53(무작위 수준) → **모델링 문제가 아니라 이 데이터 파일 자체에 예측 신호가 없다는 결론** (위 "데이터셋의 한계" 참고) | - |
| 10 | 별도 브랜치(`yh`)의 "오토인코더 + 준지도학습" 조합을 동일한 5-fold 교차검증 기준으로 검증 | CN7은 오히려 하락(F1 0.337→0.233, 임계값을 0.5→0.2로 낮춰 정밀도 희생), RG3의 "개선"은 AUC 0.49(여전히 무작위 수준)에서 임계값만 낮춘 결과 → 실질적 개선 아님 | 미채택 |

## 최종 결과 (5-fold 교차검증 평균)

**CN7**

| 모델 | precision | recall | f1 | roc_auc |
|---|---|---|---|---|
| random_forest | 0.417 | 0.333 | **0.337** | 0.954 |
| svm | 0.229 | 0.400 | 0.286 | 0.853 |
| gaussian_nb | 0.065 | 0.833 | 0.116 | 0.861 |

RandomForest의 ROC-AUC 0.954는 "양품과 불량을 구분할 능력 자체"는 꽤 높다는 뜻이다. 다만 실제로 "불량"이라고 판정했을 때 그중 42%만 맞았고(precision 0.417), 실제 불량 중 33%만 잡아냈다(recall 0.333) — 불량 관련 신호는 있지만, 학습에 쓸 불량 사례(17건)가 너무 적어서 정확하게 잡아내지는 못한다.

**RG3**

| 모델 | precision | recall | f1 | roc_auc |
|---|---|---|---|---|
| gaussian_nb | 0.021 | 0.960 | 0.041 | 0.427 |
| svm | 0.008 | 0.040 | 0.014 | 0.410 |
| random_forest | 0.000 | 0.000 | 0.000 | 0.530 |

세 모델 모두 ROC-AUC가 0.41~0.53으로 동전 던지기 수준이다. gaussian_nb의 recall 0.960이 겉보기엔 좋아 보이지만, precision이 0.021이라는 건 "불량"이라고 예측한 것 중 98%가 틀렸다는 뜻 — 거의 모든 걸 불량이라고 찍어서 recall만 높게 나온 착시다. 위 "데이터셋의 한계"에서 설명한 대로, 더 큰 표본(가이드북 결과표 기준 테스트셋에만 불량 83건 — 지금 가진 파일 전체의 3배 이상)을 확보하지 않는 이상 알고리즘 개선으로는 해결되지 않는다.

## 파일 구성

- `dataset.py` — `moldset_labeled_{product}.csv` / `moldset_unlabeled_{product}.csv` 로드 (스케일링 전 원본)
- `models.py` — GaussianNB / RandomForest / SVM 기본 하이퍼파라미터 및 생성 함수
- `semi_supervised.py` — pseudo-labeling(의사라벨) 학습 로직 (클래스별 확신도 선택)
- `evaluation.py` — 5-fold 층화 교차검증 평가 하네스 (fold마다 정규화를 다시 fit해 데이터 누수 방지)
- `hyperparameter_search.py` — GridSearchCV 기반 하이퍼파라미터 탐색

## 실행 방법

```bash
python scripts/run_semi_supervised.py                # 지도학습만 (기본, 가장 안정적)
python scripts/run_semi_supervised.py --product cn7  # CN7만
python scripts/run_semi_supervised.py --tune         # GridSearchCV 하이퍼파라미터 탐색 포함
python scripts/run_semi_supervised.py --pseudo-label # 가이드북 방식 pseudo-labeling 포함 (비권장 — 위 표 참고)
```

UI에서는 "모델 및 예측" 탭에서 제품을 선택하고 "5-fold 교차검증 실행"을 누르면 동일한 파이프라인이 실행된다.
